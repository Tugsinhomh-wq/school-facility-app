# สำมะโนผู้เรียน — ทะเบียนรายชื่อนักเรียนรายห้อง (design)

สถานะ: ผู้ใช้อนุมัติแผน · 2026-10-22

## 1. สิ่งที่ผู้ใช้ตัดสินใจ (grill-me)

- งานสำมะโนผู้เรียนของโรงเรียนมีข้อมูล **เลขประจำตัวนักเรียน (5 หลักพอดี)** และ **ชื่อ-สกุล** เท่านั้น ("เอาเท่านี้ก่อน") ห้ามเก็บฟิลด์อื่นในรอบนี้
- ใช้เป็นทะเบียนรายชื่อรายห้อง: นำเข้าจาก Excel
- รายชื่อผูกกับห้องของ **ภาคเรียนนั้น** (`classrooms` เก็บแยกตามภาคเรียน เช่น 2569/2 ห้อง ม.3/2) นำเข้าใหม่ทุกภาค ไม่มีตัวตนของนักเรียนข้ามภาค
- แม่แบบไฟล์: ระบบให้ดาวน์โหลด ชีตเดียว หนึ่งแถวต่อนักเรียน: ห้อง | เลขประจำตัว | ชื่อ-สกุล
- ใครเห็น (บังคับที่ฐานข้อมูล): เจ้าหน้าที่/หัวหน้า/ผู้ดูแลระบบเห็นทุกห้อง; ครูที่ปรึกษาเห็นเฉพาะห้องที่ตัวเองอยู่ใน `classroom_advisors`; คนอื่น (รวมผู้บริหาร) ไม่เห็น
- เก็บนานแค่ไหน: เจ้าหน้าที่กดลบรายชื่อทั้งภาคเองได้ (ยืนยันสองขั้น) ไม่มีการลบอัตโนมัติ

## 2. ผลต่อ PDPA

เดิมระบบตั้งใจไม่เก็บข้อมูลเด็ก (ความเห็นใน `facility_02_cleaning.sql`) งานนี้กลับข้อนั้น จึงต้อง
(ก) แก้ถ้อยคำหน้านโยบายความเป็นส่วนตัวให้บอกว่าเก็บทะเบียนรายชื่อ (เลขประจำตัว + ชื่อ-สกุล) ใครเห็น และลบอย่างไร
(ข) บอกในเอกสารสำรองข้อมูลว่าสำเนาเข้ารหัสมีรายชื่อด้วย เก็บ 60 วัน
(ค) ผู้ดูแลข้อมูลส่วนบุคคลของโรงเรียนควรอนุมัติก่อนนำเข้าข้อมูลจริง

## 3. การออกแบบ

- `supabase/census_01.sql` (ผู้ใช้รันเอง): ตาราง `census_students(id, classroom_id → classrooms on delete cascade, term, student_code check ~ '^[0-9]{5}$', full_name, created_at)`, unique (term, student_code); trigger ตั้ง `term` จากห้อง; RLS ตามข้อ 1; เขียนได้เฉพาะเจ้าหน้าที่
- ตัวอ่านไฟล์ล้วน `src/lib/census-import.ts`; เส้นทางแม่แบบ `/census/template`; ชั้นข้อมูล `src/lib/data/census.ts`; actions (นำเข้า, ลบรายคน, ลบทั้งภาค) เฉพาะเจ้าหน้าที่
- หน้า `/census`, `/census/[classroomId]`, `/census/import` โทน C; เปิดโมดูล `census` ใน `src/lib/modules.ts`
- เพิ่มตารางใน `BACKUP_TABLES`, `docs/backup.md`, README (ลำดับรัน SQL)

## 4. ไม่ทำรอบนี้

ฟิลด์นักเรียนอื่น, การเข้าเรียน, สรุปจำนวนส่งเขต, บัญชีนักเรียน, รูปถ่าย, ประวัติข้ามภาค, เพิ่มทีละคนด้วยมือ (ย้ายห้องให้นำเข้าใหม่)
