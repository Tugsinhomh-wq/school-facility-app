# งานอาคารสถานที่ — design (ระบบกลุ่มงานบริหารทั่วไป, รอบที่ 1)

สถานะ: ร่าง รอผู้ใช้อนุมัติ · 2026-10-21
ภาพตัวอย่างที่ผู้ใช้เห็นและตอบว่า "ดีแล้ว": https://claude.ai/artifact/1x4ik3iwJeg8FQdXhSTcNC

## 1. ทำไมต้องทำ

โรงเรียนละหานทรายรัชดาภิเษกต้องการเว็บของ **กลุ่มงานบริหารทั่วไป** แทนระบบเดิมที่ทำแค่แจ้งซ่อมกับจองห้อง
งานที่จะขึ้นเว็บมีสามงาน:

1. การจัดทำสำมะโนผู้เรียน — **พักไว้** (โรงเรียนยังไม่ได้ประชุม)
2. การดูแลอาคารสถานที่และสภาพแวดล้อม — **ทำรอบนี้**
3. การจัดระบบการควบคุมภายในหน่วยงาน — **พักไว้** (ยังไม่บรีฟ)

ผู้ใช้ต้องการ "เริ่มใหม่ทั้งหมด" โดยเหลือไว้แค่ Supabase (project `datodhjxhzcbiqdnazxt`) กับ Vercel (`school-facility-app`, deploy จาก `main`)

ความสำเร็จของรอบนี้: ครูแจ้งซ่อมและขอจองห้องได้เหมือนเดิมในหน้าตาใหม่ และ **ครูที่ปรึกษากดยืนยันเขตทำความสะอาดของห้องตัวเองได้ทุกวันบนมือถือ** ขณะที่เจ้าหน้าที่งานอาคารสถานที่เห็นทันทีว่าห้องไหนยังไม่ยืนยัน

## 2. ผู้ใช้และสิทธิ์

โครงสิทธิ์ใหม่ทั้งหมด (ผู้ใช้เลือก) ห้าบทบาท:

| บทบาท | ทำอะไรได้ในรอบนี้ |
|---|---|
| ผู้ดูแลระบบ | ทุกอย่าง + จัดการผู้ใช้ + ถังขยะ (ลบ/กู้/ลบถาวร) + กล่อง Feedback |
| หัวหน้ากลุ่มงาน | เห็นและทำได้เท่าเจ้าหน้าที่ทุกงานในกลุ่ม |
| เจ้าหน้าที่งาน | รับเรื่องแจ้งซ่อม, อนุมัติจองห้อง, จัดการห้อง, ตั้งค่าห้องเรียน-ครูที่ปรึกษา-เขต, ดูภาพรวมเขตทุกห้อง, ออกบันทึกข้อความ |
| ผู้บริหาร | ดูได้อย่างเดียว (หน้าสรุปผู้บริหาร **ยังไม่ทำรอบนี้** เก็บร่างไว้) |
| ผู้ใช้ทั่วไป (ครู) | แจ้งซ่อม, ขอจองห้อง, ถ้าเป็นครูที่ปรึกษาของห้องใด ยืนยันเขตของห้องนั้น |

- คนหนึ่งเป็นเจ้าหน้าที่ได้หลายงาน (ผู้ใช้ตอบไว้) ให้สิทธิ์ระดับงานผูกกับบทบาทหรือรายคน ไม่แยกเป็นคนละแอป
- **นักเรียนไม่มีบัญชี** ครูที่ปรึกษายืนยันแทนห้อง (ไม่เก็บข้อมูลส่วนบุคคลของเด็ก)
- บัญชีเดิมเก็บไว้ แล้ว map บทบาท: `super_admin → ผู้ดูแลระบบ`, `staff`/`room_staff → เจ้าหน้าที่งาน`, `executive → ผู้บริหาร`, `user → ผู้ใช้ทั่วไป` (หัวหน้ากลุ่มงานตั้งเองหลังย้าย)

## 3. ขอบเขต

### ทำ
- **โครงเว็บใหม่ของกลุ่มงาน**: หน้าแรกแยกตามบทบาท, เมนูตามงาน, สำมะโนและควบคุมภายในแสดงเป็น "เร็วๆ นี้" (กดไม่ได้)
- **แจ้งซ่อม** — ขั้นตอนเดิม (แจ้ง → รับเรื่อง → ดำเนินการ → เสร็จ + รูปหลังซ่อม + บันทึกข้อความ) ไม่ก้าวก่ายงานพัสดุ เปลี่ยนแค่หน้าตาและผูกเรื่องกับอาคาร/ห้อง
- **จองห้องประชุม** — เหมือนเดิม: ครูยื่นคำขอ เจ้าหน้าที่อนุมัติ ระบบกันเวลาชนกัน
- **เขตทำความสะอาดรายห้อง** (ใหม่, ดูข้อ 4)
- **ของเดิมที่ยกมา**: ล็อกอิน Google (@lrp.ac.th), Feedback, ถังขยะ, หน้า PDPA/ข้อกำหนด + ยินยอมตอนสมัคร, สำรองข้อมูลเข้ารหัสทุกคืน, บันทึกข้อความ Word/PDF
- **ออกแบบหน้าเว็บใหม่ทั้งหมด** โทนสว่างเป็นหลัก น้ำเงินโรงเรียน + ปุ่มหลักสีทอง (มีโหมดมืด) ตามภาพตัวอย่าง

### ไม่ทำรอบนี้ (non-goals)
- สำมะโนผู้เรียน, ควบคุมภายใน, หน้าสรุปผู้บริหาร
- ตรวจอาคาร/เช็กลิสต์ และ ขยะ/สวน-ต้นไม้ (เคยเลือกไว้ แต่บรีฟล่าสุดเหลือสามงาน)
- Web Push (ตัดออก)
- ทะเบียนครุภัณฑ์, ขั้นตอนพัสดุ/จัดซื้อ
- คะแนนความสะอาด, จัดอันดับห้อง, ชื่อนักเรียน

### สิ่งที่ถือว่าล้มเหลวแม้จะทำงานได้ (anti-goals)
- ครูต้องกดหลายขั้นหรือกรอกเยอะเพื่อยืนยันเขต (เป้า: ไม่เกิน 10 วินาทีบนมือถือ)
- เว็บส่งแจ้งเตือนรบกวนครู
- ข้อมูลตัวอย่างโผล่ให้คนที่ล็อกอินจริง (ระบบเดิมเคยเป็น) — โหลดไม่ได้ต้องบอกว่าโหลดไม่ได้
- เก็บข้อมูลเด็กโดยไม่จำเป็น

## 4. เขตทำความสะอาดรายห้อง

**ครูที่ปรึกษา (มือถือ)**
- เห็นเฉพาะห้องที่ตัวเองเป็นครูที่ปรึกษา: ชื่อเขต, สถานะวันนี้, ปุ่มทองปุ่มเดียว "ยืนยันว่านักเรียนทำความสะอาดแล้ว", แนบรูปได้ไม่บังคับ, แถบวันในสัปดาห์
- ไม่มีคะแนน ไม่มีชื่อนักเรียน
- (การเดาของ Claude, ผู้ใช้ไม่ได้ค้าน) ยืนยันย้อนหลังได้ แต่ระบบบันทึกว่าเป็นการยืนยันย้อนหลัง; วันหยุด/ปิดเรียนไม่นับว่าขาด

**เจ้าหน้าที่ (เดสก์ท็อป/มือถือ)**
- ภาพรวมทุกห้องของวันนี้: ห้องที่ยังไม่ยืนยันขึ้นก่อนพร้อมกรอบแดง, กรองตามอาคาร/สถานะ, "ยืนยันแล้ว 31 / 37 ห้อง"
- ตารางสรุปรายสัปดาห์ (ห้อง × วัน)
- ไม่มีแจ้งเตือนอัตโนมัติ เจ้าหน้าที่ตามเอง

**ตั้งค่า (เจ้าหน้าที่)**
- จัดการห้องเรียน, ครูที่ปรึกษาของแต่ละห้อง, เขตของแต่ละห้อง ผ่านหน้าจัดการ + **นำเข้าจาก Excel**
- ขึ้นภาคเรียน/ปีใหม่ คัดลอกชุดเดิมแล้วแก้

## 5. ข้อมูล

- **เก็บไว้**: บัญชีผู้ใช้ (`auth.users` + `profiles`), อาคาร (`buildings`), ห้อง (`rooms` รวมห้องประชุมที่จองได้)
- **ทิ้ง**: เรื่องแจ้งซ่อม, การจอง, บันทึกข้อความ, feedback, push subscriptions เดิม
- ตารางเดิมจะลบก็ต่อเมื่อผู้ใช้อ่าน SQL จริงแล้วอนุมัติ (Claude รันคำสั่งลบเองไม่ได้ ผู้ใช้รันใน SQL Editor)
- นักเรียนไม่มีในฐานข้อมูล

## 6. ข้อจำกัด

- Next.js 16 + Supabase (RLS) + Vercel; อ่าน `node_modules/next/dist/docs` ก่อนใช้ API (ตาม AGENTS.md)
- ภาษาไทยทั้งหมด, ใช้บนมือถือเป็นหลักสำหรับครู
- ทำทีละส่วน แต่ละส่วนผ่าน tsc / eslint / build / Playwright (390px + เดสก์ท็อป) แล้วเปิด PR; merge เมื่อผู้ใช้สั่ง

## 7. ปล่อยให้ผู้สร้างตัดสิน

ผังตาราง, ชื่อไฟล์/route, การแบ่ง component, จะพอร์ตโค้ดเดิมส่วนไหน (เช่น ฟอร์มแจ้งซ่อม, ปฏิทินห้อง, ตัวสร้าง Word/PDF, backup, trash) หรือเขียนใหม่ — ตราบที่พฤติกรรมตรงข้างบน

## 8. ข้อที่ Claude ตัดสินเอง (ตรวจได้)

- หนึ่งห้องมีเขตเดียว เป็นข้อความอิสระ (เช่น "ทางเดินหน้าอาคาร 2 ชั้น 1 และสวนหย่อมข้างบันได")
- วันที่ต้องยืนยัน = จันทร์–ศุกร์ เจ้าหน้าที่ตั้งวันหยุด/ปิดเรียนเพิ่มได้
- สถานะวันนี้เป็น "ยังไม่ยืนยัน" จนหมดวัน แล้วจึงนับเป็น "ขาด" ในสรุป
- นำเข้า Excel: มีไฟล์แม่แบบให้ดาวน์โหลด (คอลัมน์: ห้อง, อาคาร, อีเมลครูที่ปรึกษา, เขต)
- ตารางสรุปรายสัปดาห์ยังไม่มีปุ่มส่งออก Excel ในรอบแรก

## 9. คำตอบเพิ่มจากผู้ใช้ (2026-10-21)

- **เก็บอาคารและห้องเดิมไว้** (รวมห้องประชุมที่จองได้) เป็นข้อมูลตั้งค่า ไม่ต้องกรอกใหม่ — ข้อ 5 เปลี่ยนเป็น: เก็บบัญชีผู้ใช้ + อาคาร + ห้อง
- **หนึ่งห้องเรียนมีครูที่ปรึกษาได้หลายคน** ใครกดยืนยันก่อนก็นับเป็นของวันนั้น ระบบจดชื่อคนกด
- **สลับเว็บจริงทีเดียว** เมื่อครบทั้ง 3 ส่วน ระหว่างทำ เว็บเดิมใช้งานต่อ ดูของใหม่ผ่านลิงก์ preview ของ Vercel (ต้องไม่ทำให้ข้อมูลของเว็บเดิมเสียระหว่างทำ เพราะใช้ Supabase project เดียวกัน)
- **บันทึกข้อความรอบนี้ใช้แบบแจ้งซ่อมเดิม** การแก้เนื้อหาและรูปแบบทำรอบถัดไป เมื่อผู้ใช้ส่งตัวอย่าง
