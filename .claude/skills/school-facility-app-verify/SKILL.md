# Verifying school-facility-app changes

- Before any check: run `ls node_modules | wc -l`. If it prints 0, run `npm ci --no-audit --no-fund` first. Without it `npx eslint` dies with `Cannot find package 'eslint'`, and `tsc` reports missing `clsx`, `next/server`, and `@types/node` errors that look like code bugs.
- Tests: `npm test` runs `node --experimental-strip-types --test` over `src/lib/**/*.test.ts`. One file: `node --experimental-strip-types --test src/lib/<file>.test.ts`.
- Under the node test runner the `@/` alias does not resolve. In any module a test imports, and in the test file itself, use relative imports with the `.ts` extension, for example `import { TZ } from "./time.ts";`. Existing `src/lib` modules already do this (`cleaning.ts` imports `./time.ts`). Scratch scripts run with `node --experimental-strip-types <file>` have the same limit: import with absolute or relative paths.
- Lint the changed files: `npx eslint <files>`.
- Typecheck: `npx tsc --noEmit` can report `src/app/layout.tsx: Cannot find name 'LayoutProps'`. That error comes from Next's generated route types, which exist only after the dev server has run once. Start `npm run dev` (see below) before running tsc. If the error still shows, report it as pre-existing and check that no new errors appear beyond it.
- `tsc` and `eslint` pass even when a page crashes at runtime. A client component that imports a module pulling in `next/headers` (through `supabase/server`) only fails when the route is opened. For any UI or page change, also run `npm run dev -- -p 3123 > <scratchpad>/dev.log 2>&1 &`, `curl` the route (expect 200, not 500), and grep the log for `Import traces` or `⨯`.
- Mobile layout: a headless Playwright script in the scratchpad at 390px width can check that controls render and that a button's enabled state follows the selection. For list pages, read row order with `page.locator('ul.divide-y > li').evaluateAll(...)`, and check horizontal overflow with `document.documentElement.scrollWidth > window.innerWidth`. Look at a screenshot before claiming the layout works. Playwright is installed globally, so run scratch scripts with `NODE_PATH=$(npm root -g) node <scratchpad>/shot.js`. Read tap-target sizes with `boundingBox()` (44px for phone controls). Keep scripts, screenshots and `dev.log` in the scratchpad, not `/tmp`. For browser console warnings in `dev.log` (for example `[browser] Each child in a list should have a unique "key" prop`), establish which ones already exist on the untouched code before calling them regressions. Prefer reading the log over `git stash` on a tree with uncommitted work.
- Generated documents (memo PDF and docx exports): tests check bytes and XML, not how the page looks. Render each builder's output with `scripts/render-pages.sh <scratchpad>/out <files>` (needs `soffice`, `pdfinfo`, `pdftoppm`), then read the PNGs before claiming the layout works. Put pages from different builders side by side when comparing. A difference between builders (for example PDF centres a photo, Word left-aligns it) is a ruling to record, not a bug to hide.
- Do not edit a source file to show sample data on a page. If a screenshot needs data the demo lacks, render the component or builder from a scratch script in the scratchpad. If you must edit source for a check, record it and revert it with `git checkout -- <file>` before any commit, then confirm with `git diff`.
- In the final report, give the test count (for example "266 pass, 0 fail"). Say what was exercised: the dev route and screenshot count, the rendered page count per builder, or "live site not exercised" if none.
